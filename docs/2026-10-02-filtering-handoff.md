## 목표와 현재 방식

크리에이터 게시글에 달린 **댓글 한 건**을 `PASS` 또는 `BLOCK`으로 판정한다. 현재 실험 파이프라인은 1차 OpenAI Moderation API + 정규화·규칙, 2차 KcELECTRA 댓글 분류기다. 2차는 1차가 통과시킨 댓글을 처리하며 입력은 댓글 본문만 사용한다. 운영 API 반영이나 1차 API 제거는 결정하지 않았다.

## 이번에 한 작업

1. DKTC의 `train.csv`를 살폈다. 협박 대화 896개를 포함하지만 라벨은 **대화 전체**에 붙어 있다. 개별 발화를 자동으로 `BLOCK`으로 바꾸지 않고 후보만 추출했다. 위협 단서 중심 후보 476건, 다른 괴롭힘 범주까지 넓힌 후보 632건이 로컬 `data/restricted/dktc/`에 있다. 후보에는 오탐이 섞인다.
2. DKTC에서 Codex가 잠정 판단한 `BLOCK` 13건과 직접 작성한 `PASS` 12건으로 탐색용 `dktc-gap-v1`을 추가 학습했다. 사람 승인 데이터가 아니다. 체크포인트는 `results/kold-classifier/dktc-gap-v1/best/`에 있다.
3. 별도 합성 도전 세트 48건과 전체 dev 109건을 비교했다. 저장된 1차 결과를 사용했으며, 2차 임계값은 0.95였다.
4. `final` 47건을 **한 번** 평가했다. 저장된 1차 출력은 `results/final-stage1-20261002.jsonl`, 2차 점수는 `results/final/dktc-gap-v1-scores.jsonl`이다. `final`은 이미 소비됐으므로 다음 학습, 임계값 조정, 모델 선택에 사용하지 않는다.
5. 새 외부 데이터 후보를 조사했다. 한국어 유튜브 댓글 공개 자료는 **비상업적 연구만 허용·재배포 금지** 조건이어서, 다운로드한 로컬 원본·후보·관련 합성 초안·스크립트·문서를 사용자 요청에 따라 모두 삭제했다. 해당 자료는 학습에 넣지 않았다.

dev에서 정상 댓글 2/68을 차단한 오류는 **1차**에서 발생한 인용 댓글과 친근한 농담이었다. 2차 모델만 바꿔서는 해당 파이프라인 오류가 해결되지 않는다.

## 데이터 이용 조건과 다음 작업

- DKTC는 [CC BY-NC-SA 4.0](https://github.com/tunib-ai/DKTC)이며 대화 단위 라벨이다. 현재의 소량 보강은 탐색 실험으로만 취급한다.
- `data/raw/toxic_comment_data/`의 영화 리뷰 댓글 자료는 threat 양성이 33/9,999건이고 실제 협박과 무관한 문장이 섞여 있어 이번 목표에 부적합했다.
- 유튜브·인스타 원문을 새로 모을 때에는 출처가 **학습·배포에 허용되는지** 먼저 확인한다. YouTube [개발자 정책](https://developers.google.com/youtube/terms/developer-policies)은 스크래핑을 금지한다. 공개돼 있다는 사실만으로 원문을 학습에 넣지 않는다.
- 다음 묶음은 **댓글 한 줄**마다 출처, 사용 조건, `BLOCK/PASS`, 검수 상태, 위협 세부 유형을 기록한다. 사람 검수 전 제안 라벨은 별도 표시한다. 학습 전 새 독립 평가 분할을 고정하고 기존 dev·final 및 가까운 문장을 학습에 넣지 않는다.
- 사용자 선호: 모델 학습과 성능 테스트는 Git Bash에서 직접 실행한다. 데이터·코드·명령을 준비한 뒤 요청에 맞춰 진행한다.
