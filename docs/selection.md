# 선정 기록

비교 실험 뒤 서비스에 적용할 모델과 방식을 정한 근거를 기록하는 곳이다. 아직 실험 결과가 없으며, 아래 후보 검토는 **실험 전 초안**이다.

## 후보 검토 (이슈 #3, 초안)

무료로 쓸 수 있는 후보를 우선한다. 모델 ID·무료 한도·요금은 바뀔 수 있으므로 **실행 직전에 공식 문서로 다시 확인**하고 확인 날짜를 `configs/pilot.yaml`의 `verified_on`에 남긴다.

| 후보 | 종류 | 비용 | 다루는 유형 | 확인한 점 | 남은 확인 |
| --- | --- | --- | --- | --- | --- |
| `omni-moderation-latest` (OpenAI) | 판정 전용 분류기 | 무료 | 혐오·괴롭힘 등 13개 분류 항목 | 비LLM 전용 엔드포인트이며 무료로 쓸 수 있다. 이전 모델보다 비영어에서 개선됐다고 한다 | 한국어 댓글 정확도(실험으로 확인). 분류 항목에 스팸·개인정보가 없다 |
| Gemini flash 계열 (무료 한도) | LLM | 무료 한도 | 4개 유형 모두 | 호출해 보니 이 계정에서는 무료로 쓸 수 있는 모델이 없었다(아래 시도 결과). **이번 이슈에서 제외** | 무료로 열려 있는 모델이 생기면 다시 검토 |
| 로컬 한국어 분류기 (KcELECTRA 등) | 미세조정한 분류기 | 무료(내 PC) | 혐오·모욕 위주 | K-HATERS·K-MHaS 같은 한국어 혐오 표현 데이터셋이 공개되어 있다 | 데이터셋 이용 조건, 미세조정 비용. 이번 이슈에서는 보류 |

### 이 후보들에 대해 알아 둘 점

- **판정 전용 분류기의 한계**: 분류 항목에 스팸·광고와 개인정보가 없다. 이 유형을 못 잡은 것은 모델 성능이 아니라 구조적 한계이므로, 결과에서는 `미지원`으로 따로 집계하고 미탐에 섞지 않는다.
- **무료 한도의 데이터 이용**: Gemini 무료 한도에서는 입력한 내용이 Google의 모델 개선에 쓰일 수 있다(EEA·스위스·영국 제외 지역 기준). 합성 샘플만 쓰는 동안은 괜찮지만, 실제 서비스 댓글을 평가에 쓰려면 이 후보를 쓸 수 없다. 이 조건은 서비스 적용 단계의 제약이다.
- **무료 한도의 변동**: 한도나 제공 정책이 바뀌어 실험이 끊길 수 있다. 호출 수 상한(`max_calls`)을 두고 대체 후보를 유지한다.
- **유료 후보**: 무료 한도가 데이터 규모에 부족하면 호출 상한과 단가를 정해 소형 유료 모델을 추가한다. 비용 상한이 정해지기 전에는 실행하지 않는다.

### 다른 후보 검토 (호출하지 않음)

실제로 호출하지는 않고 제공 조건만 확인해 보류했다. 한도와 가격은 검색으로 확인한 값이므로 사용 전에 공식 문서로 다시 확인한다.

| 후보 | 보류 이유 |
| --- | --- |
| Mistral Moderation | 무료 플랜은 분당 2회라 느리고, 한국어 포함 11개 언어와 개인정보(PII) 항목을 지원한다고 한다. 무료 플랜에서 입력이 학습에 쓰일 수 있다 |
| Azure AI Content Safety | 무료 플랜 월 5,000건. Azure 계정이 필요하고 한국어 지원은 확인하지 못했다 |
| Google Cloud Natural Language `moderateText` | 한국어가 지원 언어로 명시돼 있다. 결제 계정 설정이 필요할 수 있다 |
| Groq, Cloudflare 등 | 무료 한도와 한국어 성능을 확인하지 못했다 |
| Perspective API | 2026-12-31에 서비스가 종료된다고 하여 제외 |

### `omni-moderation-latest` 관찰 (7건, 정확도 판단 아님)

- **응답 형식**: 항목별 boolean(`categories`)과 점수(`category_scores`), 전체 `flagged`가 온다. 정답 형식(`PASS`/`HOLD`/`BLOCK`, 우리 유형)과 직접 대응하지 않으므로, 본 실험에서는 응답을 우리 형식으로 바꾸는 규칙(예: 어떤 항목·점수부터 `BLOCK`/`HOLD`로 볼지)을 먼저 정해야 한다.
- **걸린 것**: 욕설·모욕 샘플(sample-003)이 `harassment`로 걸렸다. 정상 댓글과 정중한 비판(sample-001, 002), 대상 없는 강조 표현(sample-006)은 걸리지 않았다.
- **못 잡은 것**: 스팸(sample-004)과 개인정보(sample-005)는 `flagged=False`였다. 응답 분류 항목에 스팸·개인정보가 없어서 나온 구조적 한계이므로 성능 결과에 섞지 않고 `미지원`으로 따로 집계한다.
- **`HOLD`**: 경계 사례(sample-007, 정답 `HOLD`)도 `flagged=False`였다. 이 분류기는 `HOLD`를 직접 반환하지 않으므로, `HOLD`가 필요하면 점수 구간으로 정하는 규칙이 필요하다.
- **응답 시간**: 첫 호출이 두 번 모두 가장 느렸다(3건 실행 1539ms, 7건 실행 1243ms). 연결을 처음 맺는 시간이 섞였을 가능성이 있다. 나머지는 293~929ms였다.
- **한계**: 호출 7건은 응답 형식과 오류를 확인하기에만 충분하다. 한국어 정확도는 평가 데이터를 만든 뒤 본 실험에서 확인한다.

## 탐색 결과: `omni-moderation-latest`의 한국어 경계 사례 (이슈 #6, 2026-10-01)

유형별 합성 문장 41건(`data/probes.jsonl`)을 호출해 분류기가 어디까지 구분하는지 봤다. **탐색이며 정확도 지표가 아니다.** 문장은 직접 쓴 합성 문장이고 정답 라벨은 모두 사람 검수 전(`pending_human`)이며, 1회 실행, 기본 판정(`flagged`)만 사용했다. 41건 모두 성공했고 응답 시간은 중앙값 470ms, 최대 1403ms였다.

### 그룹별 결과

`flagged`는 분류기가 위반으로 판정한 건수다. "기대"는 우리 정답이 `BLOCK`이면 걸려야, `PASS`면 걸리지 않아야 한다는 뜻이다.

| 그룹 | 내용 | flagged | 기대 | 판단 |
| --- | --- | --- | --- | --- |
| `excl` | 대상 없는 감탄 욕 | 0/5 | 걸리지 않음 | 맞음 |
| `abuse` | 대상 있는 모욕 | 4/5 | 4건 걸림(1건은 정답 `HOLD`) | 명백한 모욕은 잡음 |
| `variant` | 변형 표기 | 1/5 | 감탄 1건 통과, 대상 있는 4건 걸림 | **일부만 잡음** |
| `crit` | 정중한·날 선 비판 | 0/5 | 걸리지 않음 | 맞음 |
| `sarc` | 비꼬기·반어 | 0/3 | 정답 `HOLD` | 신호 없음 |
| `hate` | 혐오·차별 | 1/4 | 걸려야 함 | **놓침이 많음** |
| `threat` | 위협 | 0/2 | 걸려야 함 | **둘 다 놓침** |
| `pii`, `spam` | 개인정보·스팸 | 0/6 | 미지원 | 구조적 한계 재확인 |
| `quote` | 욕을 인용해 고발·호소 | 1/2 | 걸리지 않음 | 맥락을 못 읽음 |
| `fp` | 정상 단어·관용구 | 1/4 | 걸리지 않음 | 일부 오탐 |

기본 판정을 `flagged → BLOCK`, 아니면 `PASS`로 단순 변환해 보면 다음과 같다(참고용).

| 정답 | 건수 | 맞게 판정 | 비고 |
| --- | --- | --- | --- |
| `BLOCK` | 19 (지원 항목 14 + 스팸·개인정보 5) | 6 | 지원 항목만 보면 6/14 |
| `PASS` | 17 | 15 | 오탐 2건(`quote-01`, `fp-04`) |
| `HOLD` | 5 | 0 | 전부 `PASS`로 처리됨 |

### 확인한 것

- **잘하는 것**: 대상을 향한 직접적인 욕설·모욕(점수 0.52~0.89)을 잡는다. 대상 없는 감탄 욕(`excl`, harassment 점수 최대 0.14)과 정중한 비판(`crit`, 0.006 이하)은 걸리지 않는다. '시발점', '개발' 같은 정상 단어는 오탐하지 않았다(`fp-01`, `fp-02`). 숫자를 끼운 변형(`variant-02`, 0.72)은 인식했다.
- **초성·글자 분리 변형은 약하다**: `ㅂㅅ같은 편집`(0.005), `ㅈㄹ하네`(0.005)는 정상 문장과 구분되지 않는 점수였다. 글자를 분리한 `씨ㅂ럴 놈아`는 0.34로, 걸리는 기준 아래였다.
- **한국어 위협을 못 잡는다**: `조심해라 밤길 다닐 때`(violence 0.001), `너 어디 사는지 안다 가만 안 둔다`(harassment 0.03)는 둘 다 정상 문장 수준이었다. 안전과 직결되는 유형이라 가장 큰 약점이다.
- **약한 수위의 차별은 놓친다**: 장애 기반 차별(`hate-04`, 0.75)만 걸렸고, 성별(`hate-01`)·국적(`hate-02`)·연령(`hate-03`) 기반 표현은 걸리지 않았다. `hate-01`은 harassment 0.28로 정상 문장보다 높았다.
- **비꼬기는 신호가 없다**: `sarc` 3건의 점수는 모두 0.01 이하로 정상 문장과 같았다. 점수 구간으로 `HOLD`를 만드는 방법은 이 경우에 통하지 않는다.
- **맥락을 읽지 못한다**: 욕을 인용해 신고하는 문장(`quote-01`)이 `harassment` 0.64로 걸렸다. 관용구 `죽는 줄 알았네`(`fp-04`)는 `self-harm` 0.29로 걸렸다. 항목별로 판정 기준이 달라서(`harassment`는 0.52에서 걸리고 0.34에서는 걸리지 않았고, `self-harm`은 0.29에서 걸렸다) 단일 점수 기준으로 비교할 수 없다.
- **스팸·개인정보**: 6건 모두 점수가 0에 가까웠다. 분류 항목에 없는 구조적 한계로, 성능 결과에 섞지 않고 `미지원`으로 집계한다.

### 해석과 다음 판단

- 이 분류기 하나로는 우리 4개 유형을 다 다룰 수 없다. 다룰 수 있는 것은 명백한 욕설·모욕과 일부 혐오이고, 변형 표기·위협·비꼬기·맥락은 보완이 필요하다.
- **보완 후보**(이번에는 검증하지 않았다)
  - 스팸·개인정보: 링크, 전화번호, 계정 형식을 잡는 규칙 기반 검사
  - 변형 표기: 전처리(초성·숫자·분리 표기를 정규화)나 한국어 전용 분류기
  - 위협·비꼬기·맥락: 정책을 따르는 LLM 판정
- **`HOLD` 변환 기준 후보**: 이 세트에서 정상 문장의 `harassment` 최댓값은 0.14, 걸리지 않은 약한 차별 표현 `hate-01`은 0.28이었다. 점수 구간(예: `harassment` 0.25~0.5)을 `HOLD`로 보는 안을 후보로 둘 수 있으나 표본이 작아 **검증이 필요하다.** 비꼬기와 위협에는 통하지 않는다.
- **한계**: 41건은 합성 문장이고 라벨은 검수 전이며 1회 실행이다. 같은 분류기가 실제 서비스 댓글에서도 같은 약점을 보이는지는 모른다. 이 결과를 선정 근거로 쓰려면 평가 데이터 구축과 라벨 검수 뒤에 다시 측정한다.

## 기록할 내용 (본 실험 뒤)

- 실험 조건: 모델 ID와 실행 날짜, 프롬프트 버전, 평가 데이터 버전과 건수
- 결과 요약: 정확도, 유형별 미탐·오탐, `HOLD` 비율, 응답 시간, 비용, 실패율
- 해석의 한계: 데이터 규모와 출처(합성/실제), 라벨러 수, 경계 사례 비율
- 선정 결과와 근거, 선정하지 않은 후보의 이유
- 운영 부담과 외부 API 실패 시 서비스 처리 방식

실험 전에는 이 문서에 결론을 적지 않는다.
