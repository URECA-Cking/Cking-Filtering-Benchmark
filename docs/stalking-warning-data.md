# 스토킹·암시적 경고 댓글 보강 후보 v1

2차 댓글 분류기가 놓치는 **사적 출입을 기다림, 반복 추적, 화자의 접근을 암시하는 경고**를 겨냥한 로컬 합성 자료다. 댓글 본문 한 줄만 입력받는 조건으로 작성했다. 실제 서비스 댓글이나 사람 검수 라벨은 아니다.

- `data/restricted/stalking_warning_v1.tsv`: `BLOCK` 24건과 비슷한 단어를 쓰는 `PASS` 24건, 총 24쌍. 모두 학습 후보이며 `train` 전용이다.
- `data/restricted/stalking_warning_v1_review.tsv`: 뜻이 갈리는 6건. `HOLD` 검토 대상으로만 두고 학습에서 제외한다. 특히 `밤길 조심해라`나 `너 나오는 거 기다린다`만으로는 위협을 확정할 수 없다.
- `data/restricted/stalking_warning_v1_train.jsonl`: 준비 스크립트가 만든 학습 후보. `reviewStatus`는 전부 `codex_provisional`이다.

`BLOCK` 후보에는 **사적인 장소나 출입을 특정하고 화자 자신이 기다리거나 따라가겠다고 말하는 단서**를 넣었다. `PASS` 후보에는 공식 행사 대기, 영상 공개 대기, 안전 조언과 신고 권유를 담았다. 단어 `기다린다`, `밤길`, `조심해` 자체를 차단 근거로 사용하지 않는다. 직접적인 위해 단서가 없는 문장은 사람 검토에서 `HOLD` 또는 제외로 바꿀 수 있다.

기존 `threat_context_v1` 학습 후보 36쌍과 함께 쓰면 총 60쌍이다. 기존 보류 12쌍과 동결된 `threat_eval_v2`는 학습에 넣지 않는다. 준비 스크립트는 기존 dev·final·도전 세트·DKTC·위협 데이터와 동일하거나 지나치게 비슷한 문장을 거부하며, 원본과 출력은 Git 제외 경로에 둔다.

```bash
python -m src.prepare_stalking_warning
```

학습 전에는 각 댓글을 **한 줄만 보고** `BLOCK`/`PASS` 여부와 사유를 사람이 확인해야 한다. `codex_provisional`을 `approved`로 자동 변경하지 않는다. 검수가 끝난 행만 별도의 승인 JSONL로 내보낸 뒤, 기존 학습 스크립트의 `--approved`에 해당 파일과 기존 승인 학습 파일을 지정한다. 출력 모델 경로는 새 경로를 사용한다. `final` 47건과 `threat_eval_v2`는 임계값 조정이나 모델 선택에 사용하지 않는다.

이 48건은 표현 다양성을 위한 시작 자료다. 실제 댓글 분포와 운영 성능을 대표하지 않으므로, 학습 후에는 사람 검수된 새로운 독립 평가 묶음에서 기존 1차+KOLD와 1차+DKTC를 모두 비교한다.
