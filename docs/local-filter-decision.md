# 로컬 전용 필터 채택 결정과 실험 결과 (2026-10-06)

이슈 #17의 결론 문서다. 1차 OpenAI Moderation API를 제거하고 **로컬 규칙 + 로컬 2차 모델**만 사용하는 구성을 채택한다. 이 결정은 아래 평가 범위 안의 근거이며, 운영 성능 보증이 아니다. 평가 세트는 대부분 합성 문장이고 라벨은 사람 검수 전이다. 문장 원문과 점수 파일은 Git 제외 경로(`data/restricted/`, `results/`)에만 둔다.

## 결정

| 항목 | 내용 |
| --- | --- |
| 채택 구성 | 정규화 → 규칙(욕설 사전·개인정보·스팸) → 로컬 모델 점수 ≥ 0.95 |
| 2차 모델 | `threat-ctx-v1-reviewed` (KcELECTRA-base 기반) |
| 제거 | 1차 OpenAI Moderation API 호출 |
| 임계값 | 0.95 (개발 세트에서 정했고 이후 평가에서 바꾸지 않음) |

[`2026-10-02-filtering-handoff.md`](2026-10-02-filtering-handoff.md)와 [`stage2-outcome.md`](stage2-outcome.md)에서 "1차 API 제거는 결정하지 않는다"로 보류했던 항목을 이 문서가 해제한다. 해제의 근거는 아래 `social_eval_v1` 비교 한 건이며, 다른 평가셋과 위반 유형으로는 검증하지 않았다.

## 왜 API가 아니라 로컬 모델인가

측정한 근거와 설계 판단을 나눠 적는다. 측정 근거는 모두 합성·잠정 라벨 평가의 범위 안이다.

**측정한 근거**
- **정확도:** `social_eval_v1` 204건에서 API가 단독으로 더한 위반은 0건이었고 정상 오차단은 2건 늘었다("죽여준다", "죽도록" 같은 관용 표현을 위협으로 봄). 규칙+로컬 모델은 78/98 차단, 정상 오차단 1/100이었다(아래 비교 표).
- **분류 항목의 한계:** 이슈 #6 탐색에서 모더레이션 API는 스팸·광고와 개인정보를 분류 항목으로 갖고 있지 않아 모두 놓쳤다. 이 두 유형은 API와 무관하게 규칙이 필요했다.
- **속도·자원:** 로컬 판정은 평균 31ms, P95 36ms, 메모리 최대 약 962MB, 콜드 로딩 약 3.6초다(i5-12400F, 2스레드, GPU 없음). API 지연은 측정하지 않았다.

**설계 판단 (측정하지 않음)**
- **정책을 우리가 조정할 수 있다.** 감탄 허용, 임계값, 규칙 예외를 코드와 데이터로 바꾼다. API는 분류 기준이 고정돼 있어 정책이 다르면 사후 보정만 가능하다.
- **외부 의존이 없다.** API 호출 실패·지연·한도·정책 변경에 대한 처리가 필요 없고, 같은 입력은 같은 결과를 낸다(모델·규칙 버전 고정).
- **댓글 원문을 외부로 보내지 않는다.** 개인정보가 든 댓글도 서버 밖으로 나가지 않는다.

**감수하는 것**
- 서버가 모델을 직접 돌려야 한다. 모델 파일은 약 436MB이고 메모리 약 1GB가 필요하다. GPU는 필요 없다. AWS 2 vCPU에서는 더 느릴 수 있어 배포 환경에서 재측정한다.
- 학습 데이터 이용 조건 때문에 상업 서비스에는 쓸 수 없고 시연 범위로 한정한다(아래 "데이터 이용 조건").
- 평가가 합성·잠정 라벨이라 운영 성능을 보증하지 않는다. 위협과 개인정보, 스팸은 아직 약하다(아래 "남은 약점").
- 노골적 성적·폭력·자해 표현은 KOLD 댓글에도 섞여 있어(학습 세트에서 단순 키워드로 찾은 댓글 중 약 70~80%가 공격성 라벨이며, 키워드 검색이라 무관한 문장도 섞여 있다) 모델이 어느 정도 배웠을 수 있다. 다만 KOLD 라벨은 공격성과 대상 유형이고 성적·폭력·자해 분류가 아니며, 이 유형의 평가 문장을 따로 만들지 않아 성능은 검증하지 못했다. 이런 유형이 문제가 되면 API를 보조로 다시 붙이는 것을 검토한다. API를 쓰는 기존 파이프라인(`src/pipeline.py`)은 삭제하지 않고 남겨 두었다.

## 모델 구성과 학습 데이터

`threat-ctx-v1-reviewed`는 두 단계로 만들었다.

1. **KOLD-only 기반 모델**: `beomi/KcELECTRA-base`를 KOLD로 3에폭 학습했다. 라벨은 `OFF=false`를 정상(0), `OFF=true`이면서 대상이 개인·집단인 댓글을 공격(1)으로 둔 학습용 근사치다. KOLD 시험셋 F1은 0.83이며 참고 지표다.
2. **위협 데이터 보강**: 위 모델 위에 소량 데이터를 얹어 1에폭 추가 학습했다.

| 보강 데이터 | 건수 | 라벨 상태 |
| --- | ---: | --- |
| DKTC 협박 대화에서 고른 발화(BLOCK)와 직접 쓴 정상(PASS) | 25 (BLOCK 13, PASS 12) | Codex 잠정, 사람 검수 전 |
| 위협·정상 대조 합성 쌍 (`threat_context_v1`) | 69 (BLOCK 34, PASS 35) | 사람 확인(`approved`) |

- 대조 합성 72건 중 3건을 제외했고, 확인 과정에서 라벨을 바꾼 행과 문장을 고친 행은 없었다. 제외로 3쌍은 한쪽만 남았다.
- 보강 데이터는 12번 반복했고, 기존 능력 유지를 위해 KOLD를 클래스당 500건 섞었다. 학습률 5e-6, 배치 8, 최대 길이 192, seed 17이다.
- 학습 입력에 평가 문장이 섞이면 중단되는 검사를 통과했다. 보호 목록에는 `final`, 갭 챌린지, 위협 평가셋 v2·v3, 위협 홀드아웃이 포함된다.
- 검수는 일반 합성 문장 기준이다. 라벨이 사람 확인을 거친 것은 69건뿐이고, 모델 전체가 사람 검수 데이터로 만들어진 것은 아니다.

## 후보 모델 비교

모두 임계값 0.95다. "1차+모델"은 저장된 1차(API+규칙) 결과와 합친 값이다.

| --- | ---: | ---: | ---: | ---: |
| KOLD-only | 26/41 | 0/68 | 33/41 | 2/68 |
| DKTC 보강 (`dktc-gap-v1`) | 30/41 | 1/68 | 35/41 | 2/68 |

**갭 챌린지 48건 (BLOCK 21, PASS 27), 모델 단독**

| 모델 | 차단 | 위협 | 비꼼 | 정상 오차단 |
| --- | ---: | ---: | ---: | ---: |
| KOLD-only | 2/21 | 0/12 | 2/9 | 0/27 |

해석은 다음과 같다.

- 채팅 욕설 데이터(약 19.6만 건, 거친 라벨)를 섞은 학습은 두 평가 모두 기존보다 나빠서 채택하지 않았다. 원인은 확인하지 못했다.
- `threat-ctx-v1`과 `-reviewed`의 차이는 개발셋 정상 1건, 갭 챌린지 위협 1건이다. 오차 범위라서 성능 차이로 읽지 않는다. 사람이 확인한 데이터를 쓴 쪽을 채택했다.
- 위협 데이터는 개발셋에서 놓친 유형을 보고 설계했다. 개발셋과 갭 챌린지 결과는 그만큼 낙관적일 수 있다.

## `final` 47건 평가 이력

`final` 47건(BLOCK 19, PASS 28)은 이번에 처음 쓴 세트가 아니다. 2026-10-02에 KOLD-only와 DKTC 보강(`dktc-gap-v1`) 구성을 이미 평가했고([`2026-10-02-filtering-handoff.md`](2026-10-02-filtering-handoff.md)), 그때 `final`은 소비됐다. 이번(2026-10-06)에는 개발셋과 갭 챌린지로 모델 선택을 끝낸 뒤 선택한 `threat-ctx-v1-reviewed` 한 모델을 추가로 평가했다. 이번 결과로 모델, 임계값, 학습 데이터를 바꾸지 않았다.

| 평가 시점 | 모델 | 모델 단독 | 1차+모델 | 정상 오차단 |
| --- | --- | ---: | ---: | ---: |
| 2026-10-02 | KOLD-only | 10/19 | 12/19 | 0/28 |
| 2026-10-02 | DKTC 보강 (`dktc-gap-v1`) | 11/19 | 12/19 | 0/28 |
| 2026-10-06 | `threat-ctx-v1-reviewed` | 12/19 | 13/19 | 0/28 |

1차(API+규칙)만으로는 5/19였다. 이전 두 구성은 협박 0/2, 비꼼 0/2였고, `threat-ctx-v1-reviewed`는 협박 1/2, 비꼼 0/2다.

- 10-02에 저장된 파일의 KOLD-only 모델 단독은 11/19로 기록돼 있다. 같은 문장의 점수가 0.9393으로 임계값 0.95 미만인데 차단으로 기록돼 있어, 그 실행의 KOLD-only 칸은 0.95가 아닌 임계값이 쓰인 것으로 보인다. 위 표는 0.95로 다시 집계한 값(10/19)이다. 1차+모델 값은 두 경우 모두 12/19로 같다. 이 임계값 차이의 원인은 확인하지 못했다.
- `final`은 이미 한 번 소비된 세트라 이번 결과는 독립된 검증이 아니다. 위협 보강 데이터는 `final`의 미탐을 포함한 미탐 우선순위([`current-miss-types.md`](current-miss-types.md))를 보고 설계했다.
- 표본이 작아 1건 차이는 우연일 수 있다. 개선의 방향만 확인한 것이다.

## API 호출 대 미호출 비교 (신규 204건)

기존 평가셋은 위협에 치우쳐 API의 기여를 보기 어려웠다. 인스타·유튜브 댓글 말투로 정상 100, 위반 98(욕설 27, 혐오 20, 스팸 19, 개인정보 13, 위협 19), 경계 6건을 새로 만들었다(`data/restricted/social_eval_v1.jsonl`). 문장은 Claude가 쓴 합성이고 라벨은 잠정이며, 기존 데이터와 80% 이상 비슷한 문장은 제외했다. 학습·임계값·모델 선택에 쓰지 않는다.

1차 결과의 근거(`reasons`)에서 API 판정(`model`)을 빼면 API 없는 구성을 재현할 수 있어, API를 1회 호출한 결과로 모든 구성을 계산했다.

| 구성 | 차단 (98) | 정상 오차단 (100) |
| --- | ---: | ---: |
| 규칙만 | 24 | 0 |
| API만 | 30 | 2 |
| 로컬 모델만 | 61 | 1 |
| **규칙 + 로컬 모델 (API 미호출)** | **78** | **1** |
| API + 규칙 + 로컬 모델 (API 호출) | 78 | 3 |

- API가 단독으로 더한 위반은 **0건**이었고 정상 오차단은 2건 늘었다. 한국어 관용 표현("죽여준다", "죽도록")을 위협으로 본 사례다.
- 유형별 규칙+모델: 욕설 27/27, 혐오 20/20, 위협 15/19, 개인정보 10/13, 스팸 6/19.
- 이 결과는 `social_eval_v1`(204건, 합성·잠정 라벨)과 임계값 0.95에서 API의 추가 탐지가 관찰되지 않았다는 범위의 관찰이다. 이 평가셋에는 노골적 성적·폭력·자해처럼 API가 강한 유형이 거의 없고, 다른 평가셋·유형·임계값에서의 API 기여는 검증하지 않았다. "API가 불필요하다"는 일반 결론이 아니다.
- 이 평가에서 로컬 구성이 같은 차단 수에 정상 오차단이 더 적었으므로 1차 API를 제거하기로 했다. 실제 댓글로 평가하거나 평가셋을 넓히면 이 판단을 다시 확인한다.

## 범위 결정

- 이번 필터는 욕설·혐오, 스팸, 개인정보, 알려진 위협 패턴을 자동으로 거른다.
- 링크가 포함된 댓글은 정상 공유(출처·공지 링크)도 모두 차단한다(링크 전체 차단 정책). 정상 링크 공유가 필요해지면 도메인 허용 목록으로 보완한다.
- 문맥이 있어야 판단되는 위협, 비꼼, 새 은어는 이후 **신고 → 사람 검수 → 추가 학습** 경로로 보완한다. 신고를 그대로 라벨로 쓰지 않고 검수 후에만 학습 데이터로 쓴다.

## 평가 도구 사용 시 주의

- `eval_full_dev`는 출력의 모델 이름을 코드에 고정한다. 첫 번째 칸은 항상 `kold`(`--base-model`), 두 번째 칸은 항상 `dktc-gap-v1`(`--dktc-model`)로 표시된다. `--dktc-model`에 다른 모델을 넣으면 그 모델 결과가 `dktc-gap-v1` 라벨로 나오므로 리포트에서 이름을 바로잡아야 한다.
- `eval_gap_challenge`는 `--candidate-model`의 상위 폴더 이름을 모델 이름으로 쓴다. 폴더명과 리포트의 이름이 같은지 확인한다.
- 두 스크립트 모두 기존 출력 파일이 있으면 중단된다. 같은 이름으로 다시 돌릴 수 없다.

## 데이터 이용 조건

- DKTC는 CC BY-NC-SA 4.0(비상업적 이용 조건)이며 최종 모델의 보강 데이터 25건에 포함된다. 서비스에 배포하려면 이용 조건이 허용하는지 먼저 확인해야 한다.
- 채팅 욕설 데이터(CC BY-NC-SA 4.0)는 채택한 모델의 학습에 쓰이지 않았다.
- KOLD는 CC-BY-NC-ND 4.0이라고 팀에서 전달받았다. 출처 링크는 확인하지 못했으므로 공식 저장소에서 다시 확인한다. 비상업 조건이라 상업 서비스에는 쓸 수 없고 시연 범위로 한정한다.
- 가공본과 모델 가중치는 공개 저장소에 올리지 않는다.

## 배포 방침과 아직 정할 것

**정한 것** (BE·인프라 협의 전 팀 방침이며, 구현하면서 확정한다)

| 항목 | 방침 |
| --- | --- |
| 서빙 | 필터를 별도 서비스로 띄운다 |
| 모델 파일 | S3에 올려 두고 서비스가 받아 쓴다(Git 불가) |
| 판정 시점 | 비동기. 댓글을 저장한 뒤 판정한다 |
| 필터 장애 | 댓글은 통과시키고, 판정하지 못한 댓글은 나중에 다시 필터링한다 |
| 사유 분류 | 사용자에게 보이는 분류(`category`)는 만들지 않는다. "필터링한 댓글 보기" 버튼을 둔다 |
| 로그 | 판정 결과를 남긴다 |

이 방침의 영향
- 비동기에 장애 시 통과이므로 판정 전과 장애 중에는 위반 댓글이 잠깐 노출될 수 있다. 욕설 노출을 절대 막는 구성이 아니다.
- 재필터링을 하려면 BE가 댓글별 판정 상태(미판정·판정 완료·실패)와 판정에 쓴 규칙·모델 버전을 기록해야 한다.
- "필터링한 댓글 보기" 버튼은 목록 응답에 원문을 담지 않고 별도 요청으로만 원문을 내려줘야 한다. 개인정보 규칙(`privacy:*`)으로 막힌 댓글은 보기 대상에서 빼야 하므로, 사용자에게는 보이지 않더라도 서버에는 `reasons`를 저장해야 한다.

**아직 정하지 않은 것**
- 컴퓨트 방식(Lambda 컨테이너, EC2, Fargate)과 월 예산 알림
- 로그에 남길 항목과 보관 기간. 원문은 BE 저장소에 이미 있으므로 필터 로그에는 댓글 ID로 연결하는 방식을 검토한다.
- "필터링한 댓글 보기"를 누를 수 있는 사람(본인·크리에이터·모든 이용자)
- 요청·응답 형식과 재시도·타임아웃 정책

## 재현 순서

학습과 평가는 Git Bash에서 직접 실행한다. 출력 폴더와 파일은 새 이름이어야 한다.

```bash
# 보강 학습: DKTC 25건 + 검수 69건
python -m src.train_dktc_gap_classifier \
  --approved data/restricted/dktc/provisional_comments.jsonl \
            data/restricted/threat_context_v1_reviewed.jsonl \
  --output-dir results/kold-classifier/threat-ctx-v1-reviewed

# 개발 109건, 갭 챌린지 48건
python -m src.eval_full_dev --dktc-model results/kold-classifier/threat-ctx-v1-reviewed/best \
  --output results/full-dev/threat-ctx-v1-reviewed-scores.jsonl
python -m src.eval_gap_challenge --candidate-model results/kold-classifier/threat-ctx-v1-reviewed/best \
  --output results/gap-challenge/threat-ctx-v1-reviewed-scores.jsonl
```
