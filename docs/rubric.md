# 평가 기준

크리에이터 게시글 댓글(1~500자)을 필터링하는 모델을 비교하기 위한 라벨 기준과 평가 원칙이다. **초안이며 팀 합의 후 확정한다.** 합의 전에는 이 기준으로 얻은 결과를 운영 정책의 근거로 쓰지 않는다.

## 입력과 범위

- 입력은 댓글 본문 한 건이다. 현재 BE 댓글 작성·수정 API([comment-api](https://github.com/URECA-Cking/Cking-BE/blob/develop/docs/domains/post/comment-api.md))의 본문과 같다.
- 댓글은 팔로워와 게시글 작성 크리에이터만 쓸 수 있다. 크리에이터와 팬이 함께 보는 공간이라는 점을 판단 기준에 둔다.
- 게시글 본문, 이미지, 이벤트 문구는 이번 범위가 아니다.

## 필터링 유형

한 댓글에 유형이 여러 개일 수 있다. 위반이 없으면 `NONE`이다.

| 코드 | 유형 | 기준 |
| --- | --- | --- |
| `ABUSE` | 욕설·모욕 | 특정 사람을 향한 욕설, 모욕, 조롱, 인신공격 |
| `HATE` | 혐오·차별 | 성별·국적·장애·출신 등 집단에 대한 혐오나 차별 표현 |
| `SPAM` | 스팸·광고 | 무관한 광고, 외부 링크 유도, 반복 도배, 구매·가입 유도 |
| `PRIVACY` | 개인정보 노출 | 연락처, 주소, 계정, 실명 등 개인을 특정할 수 있는 정보 |
| `NONE` | 위반 없음 | 위 유형에 해당하지 않음 |

판단 원칙
- **비판은 위반이 아니다.** 크리에이터나 콘텐츠에 대한 의견·불만이 정중하거나 근거가 있으면 `NONE`이다. 대상이 사람이 아니라 행동·결과물이면 `ABUSE`로 보지 않는다.
- 욕설이 있어도 특정 대상을 향하지 않는 감탄(예: 강조 표현)은 `NONE`으로 둘지 경계 사례로 둔다. 경계 사례는 `HOLD` 후보로 별도 표시한다.
- 사전에 없는 변형 표기(자음 분리, 특수문자 삽입, 초성)도 의미가 같으면 같은 유형으로 본다.
- 인용·고발 목적으로 위반 표현을 그대로 옮긴 경우는 경계 사례로 둔다.

## 처리 결과

| 값 | 의미 |
| --- | --- |
| `PASS` | 그대로 게시 |
| `HOLD` | 판단이 애매하다. 즉시 게시하지 않고 확인이 필요하다 |
| `BLOCK` | 명백한 위반. 게시하지 않는다 |

`HOLD` 이후의 처리(숨김 후 검토, 신고 처리 등)와 필요한 BE 변경은 BE 연동 설계에서 정한다. 이 저장소는 **모델이 어느 값을 반환하는지**만 평가한다.

사람이 붙이는 정답 라벨은 `expectedAction`(`PASS`/`HOLD`/`BLOCK`)과 `categories`로 나눈다. 정답이 `HOLD`인 경계 사례는 별도 집계한다.

## 오류 비용 (초안)

| 오류 | 의미 | 영향 |
| --- | --- | --- |
| 미탐 | 위반 댓글을 `PASS` | 혐오·개인정보는 피해가 크고 되돌리기 어렵다. 가장 낮게 허용한다 |
| 오탐 | 정상 댓글을 `BLOCK` | 팬이 쓴 정상 댓글이 막히면 이용 경험이 나빠지고 비판 의견을 막는다는 인상을 준다 |

- 초안에서는 **`HATE`·`PRIVACY` 미탐을 최우선으로 줄이고**, 그 제약 안에서 오탐을 낮추는 방향으로 본다.
- 애매한 경우를 `BLOCK` 대신 `HOLD`로 보내는 것은 오탐을 줄이는 수단이다. 다만 `HOLD`가 많으면 운영 부담이 커지므로 `HOLD` 비율을 따로 기록한다.
- 위 우선순위는 팀이 합의한 값이 아니다. 합의 결과를 이 절에 기록하고, 바뀌면 결과를 다시 집계한다.

## 평가 지표

- 최종 판정(`PASS`/`HOLD`/`BLOCK`) 정확도
- 유형별 미탐률·오탐률. 특히 `HATE`·`PRIVACY` 미탐은 따로 본다
- `HOLD` 비율과, 정답이 `HOLD`인 사례의 일치율
- 응답 시간(p50, p95), 호출 비용, 토큰
- 모델이 판정 이유나 유형을 함께 내면 그 일치 여부도 기록한다. 이유는 참고용이며 판정 점수에 넣지 않는다

API 호출 성공, 응답 형식 검증 통과와 판별이 정확한지는 구분한다.

## API 실패·지연

외부 모델 호출이 실패하거나 시간 안에 응답하지 않는 경우는 판별 성능과 **섞지 않는다.**
- 실패(`error`), 시간 초과(`timeout`), 미실행(`not_run`)을 별도 상태로 기록하고 판별 지표의 분모에서 제외한다. 제외한 건수는 항상 같이 보고한다.
- 실패 시 서비스가 취할 처리(통과 / 차단 / 재시도)는 BE 연동 설계에서 정한다. 이 저장소는 실패율과 응답 시간 분포만 제공한다.
- 한 모델이 실패율이 높으면 정확도가 높아도 선정 근거에서 감점할 수 있다.

## 라벨링 규칙

- 정답 라벨은 사람이 붙인다. 모델 출력을 그대로 정답으로 쓰지 않는다.
- 한 건당 라벨러 `<1~2>`명. 두 명이 다르면 경계 사례로 표시하고 합의 기록을 남긴다.
- 검수 전 후보는 `pending_human`, 검수 후 `approved`로 구분한다. `approved`만 지표에 사용한다.
- 데이터 출처와 라벨 부여 방식은 [데이터 정책](data-policy.md)에 따라 기록한다.
