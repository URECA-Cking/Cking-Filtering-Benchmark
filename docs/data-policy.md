# 데이터 정책

평가 데이터에는 욕설·혐오·개인정보 예시가 들어갈 수 있다. 이 저장소는 public이므로 아래 규칙을 지킨다.

## Git에 올리는 것

- `data/` 아래의 **공개해도 되는 소량 샘플**과 스키마. 직접 작성한 합성 문장이거나, 출처와 사용 조건을 확인한 문장만 허용한다.
- 합성 문장은 이 저장소에서 필요한 최소 수위로 쓴다. 실제 개인을 지칭하거나 실존 인물의 정보를 쓰지 않는다.
- `PRIVACY` 샘플은 가짜 값만 쓴다. 실제 전화번호·주소·계정은 넣지 않는다. 가짜 값은 형식만 같고 실제로 존재하지 않는다는 점을 `notes`에 적는다.

## Git에 올리지 않는 것

- `data/raw/`, `data/restricted/`: 수집 원본, 사용 조건이 확인되지 않은 데이터, 실제 서비스 댓글
- `results/`: 모델 원시 응답과 로컬 실행 결과
- API 키. 환경변수로만 전달하고 `.env`, 코드, 설정, 로그에 저장하지 않는다.

위 경로는 `.gitignore`에 포함되어 있다. 새 경로를 추가할 때도 같은 기준으로 판단한다.

## 공개 한국어 데이터셋 이용 조건 (확인 현황)

공개 한국어 혐오 표현 데이터셋은 실제 댓글의 분포를 보는 **참고용**으로만 쓴다. 이용 조건을 확인한 것만 쓰고, 확인되지 않은 것은 쓰지 않는다. 확인은 웹 검색 결과 기준이며, 쓰기 전에 각 저장소의 라이선스 파일을 직접 확인한다.

| 데이터셋 | 내용 | 이용 조건 | 상태 |
| --- | --- | --- | --- |
| BEEP! (kor_hate) | 연예 뉴스 댓글 약 9.4천 건, 성별 편향·혐오 라벨 | CC BY-SA 4.0 | 확인됨 (출처 표기·동일 조건 공유 의무) |
| KOLD | NAVER 뉴스·YouTube 댓글 약 4만 건, 공격성·대상·문맥 제목 | 검색으로 확인하지 못함 | **미확인 — 확인 전에는 쓰지 않는다** |
| K-HATERS | 뉴스 댓글 약 19.2만 건, 대상별 공격성 점수 | 검색으로 확인하지 못함 (저장소: ssu-humane/K-HATERS) | **미확인 — 확인 전에는 쓰지 않는다** |
| APEACH | 군중 참가자가 만든 혐오 표현 평가 데이터 | 검색으로 확인하지 못함 | **미확인 — 확인 전에는 쓰지 않는다** |
| Korean UnSmile | 약 1.9만 문장, 다중 라벨 | 검색으로 확인하지 못함 | **미확인 — 확인 전에는 쓰지 않는다** |

- 확인된 데이터셋도 **원본을 Git에 올리지 않는다.** 로컬에서만 쓰고, 문서에는 요약 수치만 남긴다. CC BY-SA 데이터를 옮겨 쓰면 동일 조건 공유 의무가 이 저장소의 파생물에도 미칠 수 있다.
- 뉴스·연예 댓글은 크리에이터 팬 댓글과 분포가 다르다. 결과를 그대로 일반화하지 않는다.
- 데이터셋마다 라벨 정의가 다르므로, 쓸 때는 `PASS`/`BLOCK` 기준으로 바꾸는 규칙을 문서에 먼저 적는다.

## 평가 세트 분리 규칙

문맥 평가 세트(`data/context_eval.jsonl`)는 `split`으로 개발용(`dev`)과 최종 평가용(`final`)을 나눈다. 최종 평가용은 방법을 확정한 뒤 한 번만 보며, 방법을 고치는 데 쓰지 않는다. 자세한 규칙은 [평가 기준](rubric.md#문맥-판별-유형-이슈-12)에 있다.

일상 댓글 평가 세트(`data/realistic_comments.jsonl`)도 같은 방식으로 나눈다. `platform`은 인스타그램·유튜브·페이스북의 말투와 게시 상황을 참고한 구분이며 실제 수집 출처가 아니다. 정상 댓글 48건과 위반 댓글 12건으로 구성해 정상 댓글 오탐을 플랫폼별 분모와 함께 본다. 직접 작성한 문장이고 라벨은 `pending_human`이므로 실제 댓글의 출현 비율이나 운영 오탐률로 해석하지 않는다.

## 기록해야 하는 것

모든 평가 데이터 행에 아래를 기록한다. 형식은 [`data/comments.schema.json`](../data/comments.schema.json)을 따른다.
- `source`: `synthetic`(직접 작성) 또는 출처 설명
- `reviewStatus`: `pending_human` 또는 `approved`
- `notes`: 라벨 판단 근거, 경계 사례 여부

실제 서비스 댓글을 평가에 쓰려면 개인정보 처리와 이용 조건을 먼저 확인하고, 이 저장소가 아니라 접근이 제한된 곳에 둔다. 확인 전에는 쓰지 않는다.
